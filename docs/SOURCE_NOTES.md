# 확인한 소스와 전달 사본의 차이

원본 별칭 `project/`는 Mac의 네이버블로그_자동화 checkout, `recent-2026-10-08/task-3/`는 최근 MARK2·MARK3 원고·이미지 최종 준비 작업, `user-project-skill/`은 해당 작업이 실제 참조한 사용자 작성 스킬입니다. 비공개 대화 원문·세션 기록·시스템 지침을 복사하지 않았습니다. 주요 checkout 루트에는 별도 `AGENTS.md`나 `.agents/skills`가 없었고, 관련 작성 지침은 프로젝트 Markdown와 사용자 `_NAVERBLOGPOST` 스킬에서 확인했습니다. checkout 안의 외부 SEO·영상 도구 스킬은 현재 글 작성 소스로 포함하지 않았습니다.

선정·표시 정책 코드와 관련 테스트는 원본을 보존했습니다. 브라우저 writer·verifier·전략 실행기에는 직접 실행 시 중단하는 참조용 guard를 추가했습니다. 계정 ID와 전화번호는 placeholder로 바꿨고 로그인 구현·프로필 설정을 제외했습니다. 편집기의 `config.js`는 `WRITE_URL: null`인 새 placeholder입니다. 편집기 자체는 원래부터 `saveOnly !== true`를 거부하므로 아래에 남아 있는 발행 코드 경로는 정상 호출에서 실행되지 않습니다.

최근 `finalize_package.py`에는 원본 입력·이미지를 요구하는 코드가 그대로 남아 있으므로 참조 파일로만 보관하고 실행을 차단했습니다. 업체명·전화·계정·개인 경로를 제거한 샘플은 문단과 이미지 역할을 보여줍니다. 실제 이미지·생성 로그·최종 SHA·기존 검수 PASS는 샘플에 이식하지 않았습니다. 사용자 스킬 사본에서는 로컬 음성 알림과 private 설정 경로를 제거하고 현장 사진 채팅방 이름을 placeholder로 바꿨습니다.

## 현재 지침과 오래된 소스의 차이

- `verify_mark_draft.cjs`에는 이미지 출처가 AI면 네이버 AI 토글도 켜져 있어야 한다는 과거 비교가 남아 있습니다. 현재 사용자 지침은 토글을 사람이 관리하며 출처로 상태를 추정하지 않도록 합니다. 참조 소스 통합 시 이 검증을 그대로 실행하지 말고 사용자가 실제 선택한 상태를 기준으로 확인해야 합니다. 원본은 수정하지 않았습니다.
- writer·본문량 검증에는 과거 manifest별 기준이 남아 있습니다. 현재 기본 이미지 10–16장 및 글별 명시 장수는 에이전트가 적용해야 합니다. 기존 수량 validator가 최신 기본 장수 전체를 자동 강제한다는 뜻이 아닙니다.
- 실제 최근 준비 manifest의 필드 구조는 오래된 `image-manifest.json` revision 구조와 다릅니다. 예제는 최근 구조를 비식별화한 것이며 `validateRevision`에 바로 넣는 fixture가 아닙니다.
- `write_mark_posts.ts`의 이름과 달리 해당 파일은 CommonJS JavaScript 형식입니다. 이 사본에서는 읽기·문법 검사만 했고 브라우저 코드 실행은 하지 않았습니다.
- 선정기의 근거 flag와 시각 검수 응답은 사실의 진위를 스스로 증명하지 않습니다. 자동 PASS 작성으로 검수 게이트를 넘으면 안 됩니다.

각 원본·사본 SHA와 변경 여부는 `source-manifest.json`에 기록했습니다. 외부 소유 소스나 전체 Git 이력은 가져오지 않았습니다.
