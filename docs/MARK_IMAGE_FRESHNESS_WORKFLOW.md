# 복원된 원고·이미지·임시저장 계약 (2026-09-26)

삭제된 원본 구현이 아니라 공개 글과 보존된 계획/manifest를 바탕으로 복원한 규격이다. 역설계 근거는 reports/blog-logic-reconstruction-2026-09-26/RECONSTRUCTION.md 참조.

1. 대표어 exact PC/모바일 원문과 조회 시각을 남긴다. `<10`은 구간이며 통계 미확인은 null이다. 통합검색 관련 블로그 URL, 서비스 적합성, 기존 글과 다른 답 및 자료를 확인한다. 검색량은 마지막 비교 기준이다.
2. 같은 계정 7일 키워드, 다른 계정 60일 의도, 기간 무관 같은 답 반복을 검사한다. 문자열 규칙만으로 의미 중복이 해결되지 않으므로 사람이 기존 본문과 차이를 검토해야 한다.
3. 원고별 최소 본문량과 이미지 역할을 계획한다. 과거 중앙값을 모든 글의 고정 장수로 만들지 않는다. 썸네일/본문 AI/실사진을 구분한다.
4. 새 글은 새 AI 생성본을 사용하며, 적합한 미사용 실사진이 있으면 함께 사용한다. imagegen만 사용하며 문단과 맞는 현실적인 한국 주거 공간을 표현한다. 가상 이미지로 실제 시공 성과를 증명하지 않는다.
5. **동일 임시저장본의 수정**은 그 초안에 이미 속한 적합한 이미지를 유지할 수 있다. 원본 manifest·계정·초안 제목·파일 SHA로 계보를 검증한다. 다른 글 재사용을 새 생성으로 표시하지 않는다. 새 주제와 맞지 않는 이미지는 교체한다.
6. 실사진 최소 장수는 없다(2026-09-27 사용자 지시). 실사진이 부족하거나 적합하지 않으면 새 Codex imagegen 이미지로 채우며 AI 이미지만으로도 작성·임시저장할 수 있다. 실사진을 사용하는 경우 출처 카탈로그·개인정보 검수·SHA를 확인한다. 단계 미상 사진은 완료·원인 확정 증거로 쓰지 않는다. 이번 복원에는 새 카카오 자료 자동 수집기는 포함하지 않았다.
7. `scripts/mark_four_stage_preflight.js`와 `scripts/lib/validate_blog_revision.cjs`가 선정·본문량·사진 출처·해시를 검사한다. 증거의 실제 진위 및 의미 중복 검토는 수집된 원문과 함께 직접 수행한다.
8. `scripts/write_mark_posts.ts <mark> <batch-directory>`는 기존 정확한 제목을 하나만 찾아 백업 후 교체한다. 원고/이미지/전화/AI 표시를 검사하고 상중하 캡처를 남긴다. 검토자가 이미지를 실제 본 후 현재 token의 PASS 파일을 기록해야 저장한다. 게이트 통과를 위해 자동 PASS를 쓰지 않는다.
9. `scripts/verify_mark_draft.cjs`는 저장 목록에서 새 제목 1건과 옛 제목 부재를 확인하고 재열어 모든 본문 블록·이미지 로딩·AI 표시를 대조한다. 이때만 FINAL_DRAFT_SAVED_VERIFIED.
10. 이 복원 편집기는 임시저장 전용이다. 발행 기능은 허용하지 않는다. 작업용 Chrome만 종료한다.

`blog_four_week_strategy.ts`는 이름만 원래 진입점과 맞춘 순차 검증/수정 실행기다. 원래의 자동 후보 탐색·장기 일정·성과 수집 전체가 복원되었다는 뜻은 아니다. 기본 실행은 로컬 검증만 한다. 저장 실행에는 SAVE_REVIEWED_DRAFTS=1을 사용하되 기존 완료 결과가 있으면 덮어쓰지 않고 중단한다.

## 2026-09-28 사용자 표시 설정

사진 캡션은 자동 작성하지 않는다. “AI 설명용 이미지”도 추가하지 않는다. 네이버 AI 활용 토글은 사용자가 직접 설정하며 자동으로 켜지 않는다. 참고문헌·검토용 외부 URL은 내부 작성 근거에 보관하고 본문에 붙이지 않는다. 이미지 생성 출처·해시·실사진 여부 기록은 유지한다.

## 자동 삽입 전면 금지 — 2026-09-28 사용자 최종 지시

- 본문 어디에도 AI 이미지 안내문·면책문을 자동 삽입하지 않는다. 예: “이 글의 이미지는 이해를 돕기 위해 AI로 제작한 예시이며 실제 고객 현장이나 측정 결과가 아닙니다.”
- 사진 아래 설명·캡션·“AI 설명용 이미지” 자동 삽입 금지. 사용자가 직접 작성한다.
- 참고문헌·출처 안내·검토용 링크를 독자용 본문에 자동 삽입하지 않는다. 내부 근거 기록에만 보관한다.
- 네이버 AI 활용 토글은 자동으로 켜거나 끄지 않는다. 사용자가 직접 관리하며, 이미지 출처로 토글 상태를 추정하지 않는다.
- 생성 이미지와 실사진의 구분·출처·해시는 내부에 정확히 유지한다. 혼합 글을 전체 AI 또는 전체 실사진으로 단정하지 않는다.
- `scripts/lib/blog_presentation_policy.cjs` 검사를 저장 전에 통과시킨다. 금지 문구·자동 캡션이 있으면 본문을 수정하고 다시 검사한다.

## 독자 관점 최종 검수 — 2026-09-28

작성자에게 필요한 지침(예시·실사 구분, 수치 생성 금지, 내부 검증·선정 규칙)을 독자에게 말하는 문장으로 옮기지 않는다. 글자 수나 금지어 검사만 통과했다고 작성 완료로 판단하지 않는다.

1. 제목부터 상담 안내까지 모든 문단을 직접 읽고 제목 질문에 답하는지 확인한다.
2. 독자에게 불필요한 면책·부정문·훈계, 실제 행동으로 이어지지 않는 추상적 설명, 반복되는 문장을 찾는다. 필요한 내용은 구체적인 확인 항목·준비 방법·선택 기준으로 고친다.
3. 금지한 AI 안내·캡션·참고문헌·내부 작성 지침이 남았는지 본문 전체를 검사한다.
4. 실제 편집 화면에서 상단·중간·하단과 수정 구간을 보고 사진 배치와 문단 가독성을 확인한다.
5. 임시저장 후 다시 열어 수정된 본문 전체와 이미지 순서를 대조한다. 사용자가 설정한 사진·캡션·AI 토글은 임의로 바꾸지 않는다.
6. 검수 기록에는 검토한 글과 수정 문단, 실제 화면 확인·재열기 결과를 남긴다. 위 지침 자체는 블로그 본문에 쓰지 않는다.

## 모든 계정 본문 형식 — 2026-09-28 최종 변경

마크1·2·3·5 모두 본문에 태그·해시태그 줄과 소제목을 넣지 않는다. 글의 메인 제목은 유지하고 본문은 사진과 자연스럽게 이어지는 문단으로만 구성한다. 소제목을 일반 문장처럼 남겨서 우회하지 않는다. 태그가 필요하면 발행 단계의 별도 태그 입력란에만 사용하며 본문에 붙이지 않는다. 과거의 소제목·태그 푸터 필수 조건보다 이 규칙이 우선한다.

## 이미지 장수 기본 규칙 — 2026-10-06 사용자 지시

앞으로 모든 블로그 글의 이미지는 글당 **10~16장**으로 구성한다. 이 범위 안에서 본문 내용과 서로 다른 이미지 역할에 맞춰 장수를 선택하고 자연스럽게 분산한다. 기존의 10장 미만 또는 16장 초과 계획보다 이 사용자 지시가 우선하며, 사용자가 해당 글에 별도 장수를 지정하면 그 지시를 따른다. 새 이미지·미사용 실사진 여부, 출처·해시 검증, 캡션·AI 표시 자동 변경 금지 및 발행 전 게이트는 그대로 유지한다.
