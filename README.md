# 네이버 블로그 작성 로직 전달 사본

2026-10-09 Mac 로컬 소스와 최근 MARK2·MARK3 준비 작업을 확인해 만든 비식별 전달 사본입니다. **독립적인 자동 발행 프로그램이 아닙니다.** 현재 흐름은 에이전트 작성 지침, 로컬 선정·검증 코드, 사람이 확인하는 이미지 검수, 기존 브라우저 연동으로 구성됩니다.

계정 설정·로그인 코드·쿠키·고객 자료·이미지 바이트는 포함하지 않습니다. 이 사본의 기본 실행은 로컬 검사만 하며 네이버에 접속하지 않습니다. 원래 프로젝트·실행 프로세스·예약 글을 변경하지 않았습니다.

## 실제 흐름

1. 대상 계정 역할과 사용자 주제를 확인하고 공개 글·임시저장·작성 중·예약 이력을 함께 대조합니다. MARK2는 천장·석고보드 등 목공 복구, MARK3는 누수 후 도배·마감 질문을 다룹니다.
2. 신규 지역 주제는 검색광고 exact PC/모바일 수요와 통합검색 결과를 수집하고, 지역명을 가려 기존 본문과 질문·답의 차이를 사람이 확인합니다. 같은 계정 7일 키워드, 다른 계정 60일 의도, 기간과 무관한 같은 답 반복을 검사합니다. `<10`은 정확한 숫자가 아닌 구간으로 유지합니다.
3. 선정기는 검증된 후보만 정렬합니다. 근거가 부족하면 `NEEDS_RESEARCH`로 남깁니다. 검색량·순위·문의 실적을 만들어 채우지 않습니다. 지역 선정은 로컬 계획이며 네이버 예약이 아닙니다. 사용자가 정한 주제 역시 기존 글과 의미 중복을 검토해야 합니다.
4. 제목 질문에 답하는 자연스러운 문단을 작성하고, 문단마다 다른 이미지 역할을 정합니다. 본문 소제목·해시태그·자동 캡션·AI 안내문·참고문헌 블록을 넣지 않습니다. 내부 검수 지침을 독자용 문장으로 옮기지 않습니다. 연락처는 운영자가 별도로 확인합니다.
5. 새 글에는 새 공식 imagegen 생성본과 적합한 미사용 실사진을 사용합니다. 실사진 최소 장수는 없으며 전부 생성 이미지여도 가능합니다. 실사진의 출처·개인정보 검수, 생성 이미지의 생성 근거·SHA를 내부에 기록합니다. 생성 장면을 고객 현장·시공 실적·측정 결과로 표현하지 않습니다. 동일 초안 수정에 한해 계보가 확인되는 적합한 기존 이미지를 유지할 수 있습니다.
6. 실제 이미지를 묶음 화면으로 살펴보고, 수정본과 문자·로고가 의심되는 영역은 개별 원본 또는 확대 화면으로 확인합니다. 사람·손·문자·워터마크·콜라주, 원고와 맞지 않는 구도 등을 확인하고 교체 사유를 기록합니다. JSON의 `PASS`만으로 실제 검토를 대신하지 않습니다.
7. 문단 ID와 정확한 문단 문자열로 이미지 삽입 위치를 고정합니다. 최근 두 글은 P01–P20 뒤에 한 장씩, P21 안내·P22 연락 문단으로 구성했습니다. 기본 장수는 10–16장이며 최근 두 글에는 사용자의 별도 20장 지시가 적용됐습니다.
8. 편집 단계는 사용자가 로그인한 정확한 대상 계정을 확인하고, 임시저장·예약 중복을 다시 확인합니다. 기존 초안 수정기는 정확한 이전 제목 한 건을 찾고 내용을 백업한 뒤 교체합니다. 모든 본문 블록·이미지 수·완전 로딩을 대조하고 상단·중간·하단을 실제로 봅니다. 현재 검수 요청 token과 일치하는 사람이 작성한 검수 응답 후 임시저장합니다.
9. 임시저장 목록의 정확한 제목 한 건과 수정 전 제목 상태를 확인하고 다시 열어 본문·이미지 순서를 대조합니다. `LOCAL_PREPARATION_COMPLETE`, `SAVE_CLICKED_EDITOR_CHECKED`, `FINAL_DRAFT_SAVED_VERIFIED`를 구분합니다. 공개 발행·예약은 별도 지시와 실제 공개 결과 확인이 필요한 다른 단계입니다.

## 로컬 실행 요건과 확인

Node.js 20 이상, npm, Python 3 표준 라이브러리만 필요합니다. 기본 검사에는 설치할 npm 의존성이나 API 키가 없습니다.

```sh
npm run check
```

검사는 기존 후보 선정·표시 정책 테스트, 비식별 샘플 문단 배치 검사, 전달 파일 검사를 실행합니다. 샘플 검사는 `SAMPLE_STRUCTURE_CHECKED`만 출력하며 실제 사진 검수·임시저장·발행 성공을 뜻하지 않습니다. 이미지 SHA·크기·생성 근거는 샘플에서 `null`, 검수 상태는 `NOT_REVIEWED_SAMPLE`입니다.

근거 없는 빈 큐 예제는 다음과 같이 조사 부족으로 종료합니다. 종료 코드 2가 예상 결과입니다.

```sh
node scripts/regional_keyword_planner.cjs examples/research-queue.json outputs/plan.json
```

실제 신규 선정에는 수집·검토한 입력이 필요합니다. 기존 초안 검증에는 기존 초안 식별자, preflight 입력, Markdown, 실제 이미지, 출처 manifest와 필요 시 로컬 실사진 카탈로그가 필요합니다. 참고 소스를 실제 편집기에 연결하려면 운영자가 저장소 밖에서 계정 설정·명시적으로 선택한 로그인 세션·Playwright 어댑터를 제공하고 현재 표시 정책에 맞게 통합해야 합니다. `reference/`를 바로 실행하는 방법은 제공하지 않습니다.

## 수동 단계와 검수 한계

의미 중복·기술 근거·사진의 실제 출처·개인정보·시각 품질·대상 로그인 계정·본문 전체 가독성은 사람이 확인합니다. 네이버 AI 활용 토글과 캡션은 사용자가 관리하며 출처로 토글 상태를 추정하거나 자동 변경하지 않습니다. 저장 후에는 실제 편집기를 다시 열어 수정 내용과 이미지 순서를 확인해야 합니다.

복원 코드는 자동 후보 탐색·장기 일정·성과 수집 전체를 구현하지 않습니다. 지침에 언급된 `kakao_field_photo_pipeline.ts`도 확인한 원본 checkout에 없었습니다. 최근 두 글의 원본 검수 기록은 로컬 준비 완료였으며 온라인 저장·발행 성공으로 해석하지 않았습니다. 이 저장소는 블로그 발행 또는 예약을 실행하지 않았습니다.

전달 파일의 허용 목록·패턴 검사와 직접 검토 결과는 `docs/DELIVERY_CHECK.md`를 참고합니다. 패턴 검사 통과는 외부 로그·환경 전체에 비밀이 없다는 증명이 아닙니다. 제외된 원본 기록과 자격증명은 저장소 밖에 유지합니다.
